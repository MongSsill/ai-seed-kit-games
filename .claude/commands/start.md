작업을 시작한다. 아래 순서대로 한다.

1. STATE.md, ASSIGNMENT.md 에서 지금 게임의 줄과 지금 단계의 줄과 "지키는 것", logs/ 에서 가장 최근 파일 하나, LESSONS.md 를 읽는다. git status 를 보고 저장 안 된 변경이 있으면 첫 줄에 알린다.
2. CLAUDE.md 의 "나" 줄에 하루에 쓸 수 있는 시간이 비어 있으면 먼저 묻는다. 내 대답을 받아 그 줄을 채운다. 이날은 0 준비 단계다. CLAUDE.md 의 일하는 규칙에서 내 말로 고칠 줄 하나를 같이 정해 고치고 /end 로 저장한다. 0 준비는 저장이 온라인 저장소까지 올라가고 다음 새 대화의 /start 가 이어받은 것을 확인한 뒤에 넘긴다.
3. 세 줄로 알려 준다.
   - 지금 어느 게임의 어느 단계이고 어디까지 왔나
   - 지난번에 배운 것 한 가지 (LESSONS.md 장부의 최근 줄. 없으면 없다고 한다)
   - 이 게임의 기준선 날짜와 서류 마감까지 남은 날
4. 기준선 날짜가 지났으면 늘리지 말고 줄이자고 말한다. 지금 게임에서 뺄 것 후보를 내고 내가 고르게 한다.
5. 오늘 할 한 가지를 제안한다. 지금 단계의 끝나는 기준에 가까워지는 일로 고르고, 30분에서 한 시간 안에 끝나는 크기로 잡고, "어떤 상태가 되면 끝인가"를 한 줄로 붙인다. 게임 폴더에 필요한 문서가 없으면 templates/ 의 양식을 복사해 쓴다.
6. 지금 단계의 끝나는 기준을 다 채운 것 같으면 다음 단계로 넘어가자고 제안한다. 기준을 하나씩 나와 확인한 뒤에 STATE.md 의 "지금 단계"를 바꾼다. G 단계가 끝나면 /retro 를 하고 다음 게임의 A 단계로 간다.

내가 좋다고 하기 전에는 게임과 기획 파일을 고치지 않는다.
