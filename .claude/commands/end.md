---
description: 작업 끝. 실험 로그를 쓰고, 상태와 배운 것 장부를 갱신하고, 저장한다.
---

작업을 마무리한다. 아래 순서대로 한다. 저장은 맨 마지막에 한다.

1. 오늘 게임 파일이 바뀌었으면 로그를 쓰기 전에 reviewer 검토를 하자고 제안한다. 내가 건너뛰겠다고 하면 넘어간다.
2. 오늘 한 일을 logs/YYYY-MM-DD.md 에 쓴다. 양식은 logs/_template.md 다. 같은 날짜 파일이 있으면 맨 아래에 "## 이어서 (시:분)" 제목을 달고 양식 전체를 새로 한 벌 쓴다. 앞에 쓴 것은 고치지 않는다.
   - "게임과 단계", "AI에게 맡긴 것", "3 작게 쪼개기", "4 AI 협업 세팅"은 이 대화에서 실제로 있었던 일만 적는다. 꾸미지 않는다.
   - "내가 한 것", "1 상황 정의", "2 문제·목표 정의", "AI가 틀렸던 곳과 내가 잡은 방법"은 네가 채우지 않는다. 내게 묻고, 내 대답을 내 말 그대로 적는다. 내가 "적당히 써 줘"라고 해도 쓰지 않고 "(내가 채울 칸)"이라고 남긴다.
   - 사람 칸에는 내 말 외에 아무것도 덧붙이지 않는다. 짚을 것이 있으면 로그 맨 아래에 "AI 메모:" 줄을 따로 둔다.
3. 오늘 장부에 적지 않고 지나간 것이 있는지 본다. 내가 네 결과를 고치게 한 일, 내가 같은 설명을 다시 한 일, 네가 틀렸던 것을 LESSONS.md 장부에 한 줄씩 적는다. 없으면 없다고 말한다.
4. 장부에 같은 종류가 두 번 이상이면 CLAUDE.md 의 "자라는 규칙"대로 제안을 하나 한다. 내가 좋다고 할 때만 바꾸고, 바꿨으면 "고친 이력"에 적는다.
5. STATE.md 에서 오늘 한 게임의 칸(지금 단계, 지금 어디까지, 다음 한 가지)과 맨 위의 마지막 작업일, 막힌 것을 고친다. 게임 폴더의 docs/tasks.md 에서 끝난 작업의 상태와 실제 걸린 시간을 고치고, 방식이 바뀐 작업은 그 줄을 고친다.
6. 하나를 묻는다. "오늘 만든 것 하나를 골라, 어떻게 돌아가는지 두세 문장으로 설명해 볼래요?" 내 설명에 틀린 곳이 있으면 짚어 주고, 내 설명을 로그의 "5 실행하며 익히기"에 내 말 그대로 붙인다. 내가 건너뛰겠다고 하면 넘어간다.
7. 저장한다. git add, git commit (메시지는 오늘 한 일 한 줄), git push 를 하나씩 따로 실행한다. 다른 명령과 묶지 않는다. 저장소나 원격이 없으면 무엇이 없어서 저장하지 못했는지 말한다.
