## 0. AI 개발 에이전트 필독

1. 이 문서는 **확정된 기획**과 **추천·가설·미결정 사항**을 구분한다. **[확정]**이 아닌 항목을 독단적으로 확정하지 말 것.
2. 구현을 시작할 때는 이 문서의 **미결정 사항(§11)**과 **최소 프로토타입(§12)**을 먼저 확인할 것. 미결정 사양이 구현을 막으면 가정을 명시하고 최소 구현으로 진행하되, 임의의 기능 확장은 하지 말 것.
3. 우선순위는 **태그의 핵심 재미 구현 > 매끄러운 단계별 학습 > 연출·콘텐츠 규모**다.
4. 태그는 캐릭터의 단순 교체가 아니라 **다음 캐릭터의 기술 자동 발동과 행동 연계**를 의미한다.
5. **이동 자체에는 PERFECT 보너스가 없다.** 전투에서 적중 직후의 태그만 PERFECT 가능하다.
6. **빨강/파랑/바람**은 임시 식별명이다. 기존에 준비한 도트화 캐릭터 에셋을 사용할 계획이나 실제 에셋 파일·애니메이션 준비 여부는 별도 확인 필요.
7. 참고 캐릭터의 원작은 *몬길: 스타다이브*다. 외부 공개·채용 제출 및 에셋 사용 시 원작의 지식재산권/2차 창작 이용 조건을 별도로 확인할 것. 사용 허가가 확인되었다고 가정하지 말 것.

### 상태 표기법

- **[확정]**: 사용자와 대화에서 채택한 규칙/목표
- **[잠정]**: 제안됐으나 수치·방식 최종 검증 및 확정 전
- **[미결정]**: 서로 다른 방안이 존재하거나 사용자 확정이 없는 항목
- **[구현 제안]**: AI가 구현 편의를 위해 제시할 수 있으나 원기획의 확정 규칙은 아닌 사항

### 1.1 포트폴리오 목적 — 두 가지 핵심 역량 [확정]

**목표 A — 독창적인 핵심 재미 시스템의 실제 구현**
- 타이밍을 맞춰 태그했을 때 명확한 추가 보상이 발생한다.
- 이전 캐릭터의 행동과 다음 캐릭터의 행동이 자연스럽게 이어진다.
- 캐릭터별 동일한 고유 기술을 이동과 전투에 모두 사용한다.
- 기존 게임의 태그 기능을 단순 모방하지 않고 **에코·공간적 연계·타이밍 보상**의 결합에서 독자적 플레이 경험을 검증한다.

**목표 B — 튜토리얼형 스테이지의 자연스러운 학습 흐름을 통한 레벨 디자인 역량 입증**
- 스테이지의 지형, 적, 배치를 이용하여 핵심 행동을 **발견 → 학습 → 응용 → 숙달 → 최종 검증**하게 만든다.
- 설명 문구만으로 가르치는 대신 자연스럽게 사용해야 하는 상황을 제공한다.
- 보스전은 새로운 조작을 소개하기보다 기존 4개 스테이지의 학습 내용을 검증한다.

### 1.2 핵심 플레이 순환 [확정]

```text
이동/전투 중 캐릭터 고유 기술 활용
        ↓
태그 입력 → 다음 캐릭터로 교체 + 다음 캐릭터 기술 자동 발동
        ↓
[공격 적중 직후의 판정 구간에서 태그한 경우]
PERFECT → 이전 캐릭터 에코 공격 유지 + 태그 자원 반환
        ↓
후속 기술 적중 → 추가 PERFECT 기회 및 연속 태그
        ↓
연계 게이지 누적 → 3인 합동 필살기
```

※ 공격이 없는 순수 이동에서는 PERFECT 판정/추가 보상을 요구하지 않는다.

## 2. 기본 조작 및 태그

### 2.1 기본 조작 철학 [확정]

- 태그 버튼 입력 한 번으로 캐릭터가 교체되고 **다음 캐릭터의 고유 기술이 자동 발동**한다.
- NORMAL 태그에서도 자동 기술 발동이 발생한다. PERFECT에 성공해야만 기술이 발동하는 구조가 아니다.
- 태그는 전투와 이동에 동일한 기본 시스템을 사용한다.
- 캐릭터별 고유 기술은 직접 사용도 가능한 방향으로 논의됐으나, **직접 사용 버튼과 태그 발동의 관계는 아직 최종 확정하지 않았다**.

### 2.2 입력 배치 [잠정]

| 동작 | PC 키 예시 | 상태 |
|---|---|---|
| 이동 | 좌/우 방향키 | [잠정] |
| 점프 | Space | [잠정] |
| 기본 공격 | J | [잠정] |
| 고유 기술 직접 사용 | K | [미결정: 버튼 존재 여부] |
| 태그 | L | [잠정] |
| 합동 필살기 | U | [잠정] |

조작키는 임시 예시이며, 확정 입력 명세가 아니다.

### 2.3 NORMAL / PERFECT [확정]

| 구분 | NORMAL 태그 | PERFECT 태그 |
|---|---|---|
| 캐릭터 교체 | O | O |
| 다음 캐릭터 고유 기술 자동 발동 | O | O |
| 이전 캐릭터의 잔류 공격(에코) | X | O |
| 태그 자원 반환 | X | O |
| 이동 성능 추가 보너스 | 없음 | 없음 (순수 이동에서는 PERFECT 판정하지 않음) |
| 연계 게이지 보상 | 일반 보상은 조건·수치 미확정 | NORMAL보다 큰 보상 방향 채택, 수치 미확정 |

### 2.4 PERFECT 판정 [확정 / 시간 잠정]

- **조건:** 공격이 실제 적에게 적중한 **직후** 태그한다.
- **허공에서 공격 모션만 맞춘 경우:** PERFECT 없음.
- **순수 이동:** PERFECT 추가 보상 없음; 이동에 타이밍 정밀도를 강제하지 않는다.
- **실패:** PERFECT 판정 시점을 놓치면 NORMAL 태그로 작동하며 별도 벌칙 없음.
- **타이밍 윈도우:** `250ms`는 추천 초기 테스트값이지 최종 확정값은 아님. 실측 후 변경 가능.
- **다단히트 기술:** 기술 한 번당 PERFECT 기회를 1회만 제공하는 방식이 잠정적으로 추천됐다. 다단히트 세부 처리 미확정.
- **다음 연계:** 태그로 자동 발동된 후속 기술이 적중하면 새로운 PERFECT 기회 생성 가능.

### 2.5 태그 방식의 미결정 사항

- **교체 순서:** `빨강 → 파랑 → 바람 → 빨강` 고정 순서인지, 대기 캐릭터 중 자유 선택인지 **미결정**. 두 방식 모두 예시로 등장했으므로 확정된 것처럼 코딩하지 말 것.
- **교체 등장 위치:** 이전 캐릭터 위치 계승, 공격 대상 추격 보정, 시전 방향 처리 등의 정밀 규칙 **미결정**.
- **입력 방향:** 태그 중 다음 캐릭터의 기술 방향은 입력 중인 방향키를 우선 활용하는 방안이 제안됐으나, 기술별 예외 및 결정 규칙 **미결정**.
- **일반 공격으로 PERFECT 가능 여부:** 고유 기술의 지정 타격에 한정하는 방안이 추천됐지만 아직 **미결정**.

## 3. 태그 자원: 스택 방식

### 3.1 선택 방향 [잠정]

초기에는 단일 쿨타임(예: 1.5초)을 검토했으나, **세 캐릭터를 연속으로 이동에 사용할 때 쿨타임이 흐름을 끊는 문제** 때문에 **2회 충전형 스택**을 더 적합한 기본 프로토타입 안으로 추천했다. 사용자가 세부 수치까지 개별 확정한 것은 아니므로 **스택형은 유력한 설계안, 값은 테스트용**으로 취급한다.

| 항목 | 초기 테스트값/규칙 | 상태 |
|---|---|---|
| 최대 태그 스택 | 2 | [잠정] |
| 태그 1회 사용 | 스택 -1 | [잠정] |
| PERFECT 성공 | 사용한 스택 1개 즉시 반환 | [확정된 보상 방향, 구체 구현 잠정] |
| 자연 회복 | 2초마다 1개 회복 | [잠정] |
| 스택 0 | 태그 불가 | [잠정] |
| 이동 중 회복 | 공통 회복 규칙 적용 | [잠정] |

- PERFECT 반환은 **전체 스택을 최대로 채우는 효과가 아니라 해당 태그로 사용한 1개를 반환**하는 방식으로 제안됐다.
- 공중 이동 도중 스택이 모자라 추락하거나, 발판 앞에서 회복을 기다리는 상황이 반복되지 않도록 스테이지 배치를 설계해야 한다.
- 스테이지 진입/재시작 시 스택 회복 처리 방법은 **미결정**. 초기 테스트에서는 최대치로 시작시키는 방안을 고려할 수 있다.

### 3.2 검증 포인트

- 이동에서 세 캐릭터의 기술을 연속 사용하려면 태그 횟수와 스택이 충분한가?
- PERFECT 연속 성공으로 스택이 무한히 유지될 때 보스가 무력화되는가?
- 적이 경직되지 않는 구간, 사거리 이탈, 기술 적중 실패 등으로 무한 연계가 자연스럽게 끊기는가?
- 별도 강제 연계 횟수 제한은 **아직 채택하지 않음**.

## 4. 캐릭터별 고유 기술

세 캐릭터의 기술은 **이동과 전투에 공통 적용**한다. 아래에서 사용자가 직접 바꾼 핵심 컨셉은 [확정], 수치와 적중 효과는 대부분 [잠정]이다.

### 4.1 빨강 — 용 변신 화염 돌진 [핵심 컨셉 확정]

**컨셉**
- 작은 붉은 용으로 변신하여 **불길에 휩싸여 전방으로 돌진**한다.
- 돌진 도중 **공격 판정이 존재**한다.
- 특히 공중 적이 돌진 경로에 있더라도 **적을 공격하면서 돌파**할 수 있도록 설계해 이동 중 공중 피격·낙하 위험을 줄이는 이점을 준다.

**전투 활용**
- 돌진 경로상의 적 타격.
- 타격 직후 PERFECT 태그의 진입점이 된다.
- 적을 밀어내는 효과는 이전 초안에 존재했지만 최신 용 돌진 사양에서는 **밀어내기 유무 미확정**.

**이동 활용**
- 주로 수평 방향 이동, 빈 공간 또는 공중 적이 있는 구간 돌파.
- 돌진 속도·거리·지속 시간·피격 내성은 미확정.

**중요한 설계상 구분**
- **공격 판정이 있다고 피격이 자동으로 방지되는 것은 아니다.**
- 일반 접촉 공격에 경직되지 않도록 별도 규칙을 부여하는 방안이 추천됐지만 **완전 무적, 슈퍼아머, 충돌 우선순위의 상세 정책은 미결정**.
- 보스의 강력한 공격까지 무시하지 않게 설계하는 것이 추천 방향이다.

### 4.2 파랑 — 빙결 활주 [A안 확정]

**컨셉**
- 방향키로 방향을 지정하고, 그 방향으로 **일시적인 얼음 경로를 생성하면서 자동으로 빠르게 이동**한다.
- 얼음 경로는 단순 연출을 넘어 후속 캐릭터가 활용할 수 있는 **임시 발판**으로 제안됐다.
- **자유롭게 발판을 하나씩 놓고 직접 걷는 B안은 채택하지 않음.**

**초기 프로토타입 파라미터 [잠정]**

| 속성 | 값/규칙 | 상태 |
|---|---|---|
| 발동 | 파랑으로 태그 시 기술 자동 발동, 직접 스킬 사용은 미결정 | [확정/미결정] |
| 이동 방식 | 방향 지정 후 자동 활주 | [확정] |
| 지원 방향 | 좌/우/좌상/우상 4방향을 우선 추천. 8방향 전부는 미확정 | [미결정] |
| 기술 지속 | 0.35초 예시 | [잠정] |
| 활주 거리 | 캐릭터 폭 약 5배 예시 | [잠정] |
| 얼음 유지 | 경로 생성 완료 후 1.5초 예시 | [잠정] |
| 경로 충돌 | 위에서 착지 가능, 아래에서 통과 가능한 단방향 발판 추천 | [잠정] |
| 중복 생성 | 기존 경로 제거 후 새 경로 하나만 유지 추천 | [잠정] |
| 소멸 예고 | 소멸 약 0.3초 전 균열 등 시각 피드백 | [잠정] |
| 태그 후 | 남은 경로는 유지 | [추천·잠정] |

**전투 활용 [추천·잠정]**
- 얼음 활주 중 적과 충돌하면 **타격 + 짧은 경직**을 부여하는 간단한 방식.
- 적중 직후 PERFECT 태그 가능.
- 지속 감속, 빙결 상태이상 등의 별도 상태이상 시스템은 **초기 범위에 넣지 않는 것 추천**.
- 얼음 경로는 **NORMAL 태그 후에도** 남는다. 전투 PERFECT의 추가 보상은 별도의 에코 공격·스택 반환이며, 경로 잔류 자체가 PERFECT 보상이 되지 않도록 구분한다.

**핵심 레벨 디자인 잠재력**
- 빈 공간에 임시 다리 형성.
- 다른 캐릭터가 잠시 얼음 발판에 착지하거나 추가 기술을 연결.
- 적을 타격하면서 이동하고, 뒤이어 다른 캐릭터가 경로를 이용.

**기술적 주의**
- 경사/대각선 얼음 경로를 '단방향 실제 발판'으로 만드는 충돌 처리는 처음 예상보다 복잡할 수 있다. 프로토타입에서 충돌 정책을 먼저 검증할 것.
- 얼음의 최초 생성 시점별로 소멸 시간을 따로 계산하기보다는 **전체 경로가 생성 완료된 뒤 동시에 소멸 카운트**를 시작하는 방안이 추천됐다.

### 4.3 바람 — 상승 기류 [핵심 컨셉 확정]

**컨셉**
- 상승 기류를 사용해 **수직으로 솟구치는 이동 기술**.
- 높은 발판에 도달하고 공중에서 높이를 확보하는 역할.

**전투 활용 [잠정]**
- 상승 구간에 공격 판정을 부여하여 적을 띄우는 방식이 제안됐다.
- 전투 효과·경직·피격 판정·상승 속도는 아직 확정되지 않음.

**역할 분리**
- 빨강 = 공격적인 수평 돌파
- 파랑 = 방향 지정형 얼음 경로 생성 + 자동 이동
- 바람 = 수직 상승

## 5. PERFECT 에코 공격과 전투 연계

### 5.1 에코 개념 [확정]

PERFECT 태그 성공 시, 교체되어 나가는 캐릭터는 **이미 사용 중이던 공격의 남은 동작/공격 판정**을 마무리하는 짧은 에코 형태로 잔류한다. 동시에 새 캐릭터가 고유 기술을 자동 발동한다.

- 이전 캐릭터를 별도로 조작하지 않는다.
- 에코는 별도 캐릭터가 영구 소환되는 것이 아니다.
- 이전 공격 종료 후 에코는 사라지는 형태가 우선 추천됐다.
- 에코가 이동 중에도 생성되는지: **순수 이동에 PERFECT가 없으므로 별도 이동 에코 보상 없음**.
- 에코 공격의 추가 타격 횟수·범위·대미지 배율 등은 미결정.

### 5.2 전투 예시 (기능 관계 설명용)

```text
빨강: 용 화염 돌진으로 적 타격
    ↓ 적중 직후 태그
PERFECT 성공
    ├─ 빨강: 기존 돌진 공격의 남은 부분을 에코로 지속
    ├─ 파랑/바람 중 다음 캐릭터: 고유 기술 자동 발동
    └─ 태그 스택 1개 반환 + 연계 게이지 추가 획득
    ↓
후속 캐릭터가 공격 적중
    ↓
새로운 PERFECT 입력 기회
```

주의: 예시의 후속 캐릭터 선택은 **교체 순서가 결정되어야 확정**할 수 있다.

### 5.3 핵심 구현·밸런스 주의

- 기술 1회당 PERFECT 기회가 중복 생성되지 않도록 이벤트 ID·타격 ID 관리 필요.
- 적 다수 타격 시 어떤 적중을 판정 기준으로 삼을지 미결정.
- 후속 캐릭터가 너무 멀리 등장하여 자동 기술이 빗나가지 않도록 위치 보정 정책 필요(미결정).
- 무한 경직 콤보를 막기 위한 보스의 슈퍼아머/패턴 중 경직 저항 등은 검토 대상이며 상세 정책 미결정.

## 6. 연계 게이지 및 3인 합동 필살기

### 6.1 연계 게이지 [확정된 방향]

- 캐릭터별이 아닌 **파티 전체 공용 게이지 1개**.
- 전투 태그/공격 적중 기반으로 충전하며, **PERFECT에 더 큰 보상**을 부여하는 방향.
- 게이지 100%에서 **3인 합동 필살기** 사용.
- 허공에서 태그만 반복해 충전하는 구조는 지양.
- 수치 예시 `NORMAL +10`, `PERFECT +25`는 설명용으로 등장했을 뿐 **미확정**.

### 6.2 필살기 연출 [잠정]

1. 빨강: 용 화염 돌진으로 공격 시작.
2. 파랑: 빙결 기술을 이용해 연계 타격.
3. 바람: 상승 기류 기반 후속 타격.
4. 세 캐릭터가 함께 마무리하는 합동 공격.

※ 이전 연출 예시에는 파랑의 '상승 베기'와 바람의 '내려찍기'가 등장했으나 **이후 캐릭터 기술 자체가 수정되었으므로 그대로 구현하지 말 것**. 현재의 **용 돌진 / 빙결 활주 / 상승 기류**에 맞춰 최종 연출을 다시 설계해야 한다.

- 구현 시간 절감을 위해 기존 기술 애니메이션을 재활용하고 마지막 합동 타격에 특수 이펙트를 추가하는 방안 추천.
- 보스 처치에 필살기를 **필수 조건**으로 강제하지 않는 방향 추천.

## 7. 이동과 전투에 공통 적용되는 태그 규칙

1. 캐릭터가 교체되면 **새 캐릭터가 기술을 자동 발동**한다. [확정]
2. 순수 이동에서는 태그 입력을 PERFECT 판정하지 않는다. [확정]
3. 이동에서 정확한 태그 타이밍에 따른 속도·거리 추가 보상은 없다. [확정]
4. 이동의 숙련도는 **어느 위치에서 어떤 기술을 연결하는가**로 나타난다. [설계 의도]
5. 전투 중 공격이 적중한 직후에만 PERFECT 보상 기회가 생긴다. [확정]
6. 공격 판정이 붙은 이동 기술(빨강 돌진, 파랑 활주 추천, 바람 상승 추천)은 적을 맞히면 전투 PERFECT로 이어질 수 있다. [빨강 확정, 나머지 공격 판정 잠정]
7. 태그 스택은 이동과 전투에 공통 적용하는 방향이다. [잠정]

### 이동 연계 예시

```text
빨강 용 돌진 → 바람 상승 기류 → 파랑 얼음 경로 활주
   수평 이동         높이 확보          임시 경로로 착지/횡단
```

이 예시는 기술 간 시너지를 보여주지만, **자유 선택 태그가 확정되지 않은 상태에서 특정 순서를 고정하는 명세는 아니다**.

## 8. 5개 스테이지: 학습 기반 레벨 디자인

### 8.1 확정된 구성 원칙

- **총 5개 스테이지. Stage 5는 최종 보스전.**
- 전체 목표 시간 **5~10분**.
- 스테이지는 시스템을 하나씩 추가하는 목적이 아니라 **같은 핵심 기술을 여러 맥락에서 활용해 배우는 구조**.
- 지나친 설명 텍스트 없이 지형과 적의 배치로 플레이 행동 유도.
- 필수 안내가 전혀 없으면 막힐 수 있으므로 최초 조작 안내 1회 등 최소 UI는 허용.
- 초반에 전투의 재미를 너무 늦게 소개하지 않도록 Stage 2에 PERFECT 학습 배치.

### 8.2 스테이지 역할(구조 합의, 구체 맵 미확정)

| Stage | 역할 | 학습·검증 요소 | 맵/적 배치 아이디어(잠정) |
|---|---|---|---|
| 1 | **발견 — 태그 이동** | 이동·점프·태그 시 기술 자동 발동 | 일반 점프로 넘기 어려운 틈, 빨강 용 돌진 또는 파랑 얼음 경로로 돌파할 수 있는 구간 |
| 2 | **학습 — 태그 전투** | 공격 적중 후 PERFECT, 에코 공격 | 단순한 적 1종, 처음에는 안전한 타격 환경, 타이밍 피드백 |
| 3 | **응용 — 연속 태그** | 태그 스택, 세 캐릭터 이동·전투 연계 | 높은 발판 + 빈 공간 + 소수 적; 수평/수직/얼음 지형의 조합 |
| 4 | **숙달 — 복합 상황** | 이동과 전투를 결합, 연계 게이지와 3인 필살기 | 적과 장애물 동시 배치, 필살기 활용 기회 |
| 5 | **최종 검증 — 보스** | 이동 회피, PERFECT 연계, 에코, 게이지 활용 | 소수의 읽기 쉬운 보스 패턴, 이전 4개 스테이지의 응용 |

### 8.3 초기 시간 배분(잠정)

- Stage 1: 45~60초
- Stage 2: 60~90초
- Stage 3: 60~75초
- Stage 4: 75~105초
- Stage 5: 90~150초
- 합계 약 5분 30초~8분 (재시도 시간은 별도)

### 8.4 최종 보스 [핵심 구조 확정 / 패턴 잠정]

새 기술 학습보다 기존 학습의 검증에 집중한다.

| 보스 패턴 후보 | 플레이어가 활용할 기존 기술 |
|---|---|
| 지면 충격파 | 바람 상승·점프 등 수직 이동 |
| 전방 돌진 | 태그 이동으로 회피 |
| 공격 후 빈틈 | 공격 적중 직후 PERFECT 태그 |
| 무방비 구간 | 3인 연속 기술 연결 |
| 체력 후반부 | 누적 게이지의 합동 필살기 활용 |

보스 상세 AI, 체력, 공격 간격, 취약 시간, 패턴 전환 조건은 **미결정**.

### 8.5 튜토리얼 레벨 디자인에서 피할 것

- PERFECT에 실패하면 이동할 수 없는 길(이동에는 PERFECT 보상 없음).
- 설명문을 읽지 않으면 진행을 이해할 수 없는 구간.
- Stage마다 완전히 새로운 조작·기믹을 지속적으로 추가하는 설계.
- 특정 태그 스택 회복을 기다리기만 해야 하는 발판 배치.
- Stage 5에서 처음 등장하는 필수 시스템.

### 9.2 담당 역할 [확정]

**AI 개발 에이전트**
- 이동/점프/태그/스택/전투/에코/게이지 시스템 구현
- 적/보스, 스테이지 데이터, HUD, 기술 애니메이션 연동
- 오류 수정, 테스트용 디버그 도구 작성, 코드 모듈화

**사용자(기획·테스트·수정)**
- 우선순위·규칙 결정, 플레이 테스트, 난이도 평가, 수정 사항 제시
- 캐릭터 리소스 및 연출의 품질 검토
- 시스템의 고유한 재미와 레벨 디자인 학습 효과 평가

### 9.3 AI 구현 시 코드 구조 제안 [구현 제안]

아래는 개념 분리 예시이며 **확정 파일 구조나 강제 API가 아니다**.

```text
src/
  core/           # 게임 상태, 씬 전환, 입력
  player/         # 캐릭터 상태/기술/교체
  combat/         # 히트 판정, PERFECT 윈도우, 에코 공격
  systems/        # 태그 스택, 연계 게이지, 필살기
  levels/         # Stage 1~5 구성 데이터, 공통 기믹
  enemies/        # 일반 적, 보스 상태 머신
  ui/             # 스택/HUD/태그 가능 피드백
  assets/         # 도트, 이펙트, 사운드
```

**권장 구현 원칙:** 기술 데이터와 태그 판정 로직을 분리하고, Stage마다 공통 시스템을 복사하지 말고 공유할 것.

## 10. 프로토타입 확인 기준 및 테스트

### 10.1 최소 플레이 가능 프로토타입(First Playable)

**핵심 범위**
1. 평지+틈+높은 발판으로 이루어진 시험 맵 1개.
2. 빨강과 파랑(필요 시 바람 추가)의 최소한의 플레이어 표현.
3. 이동/점프/기술 실행/태그 시 후속 기술 자동 발동.
4. 적 1종 및 타격 이벤트.
5. 공격 적중 직후 태그가 PERFECT로 판정되고, 에코 공격이 남는다.
6. 태그 스택 소모 및 PERFECT 반환.
7. 파랑의 얼음 활주가 생성한 임시 경로를 후속 캐릭터가 이용할 수 있다.

**보스·고급 연출·완성된 5개 스테이지는 첫 프로토타입 필수 범위에서 제외.**

### 10.2 기능 테스트 케이스(초안)

| ID | 입력/상황 | 기대 결과 |
|---|---|---|
| T01 | 적 없음, 태그 사용 | 정상 교체 + 후속 기술 자동 발동, PERFECT 없음 |
| T02 | 공격 적중 직후 유효 시간 내 태그 | PERFECT, 에코 공격, 스택 반환 |
| T03 | 공격이 빗나간 직후 태그 | NORMAL 처리 |
| T04 | 공격 적중 후 판정 시간이 경과한 뒤 태그 | NORMAL 처리 |
| T05 | PERFECT 후 다음 기술 적중 | 다시 PERFECT 기회를 만들 수 있음 |
| T06 | 순수 이동 중 태그 | 이동 추가 보상 없이 후속 기술 발동 |
| T07 | 파랑 활주로 빈 공간 횡단 | 얼음 경로 생성 및 자동 이동 |
| T08 | 파랑 활주 후 다른 캐릭터로 태그 | 얼음 경로 일정 시간 유지, 후속 캐릭터가 착지 가능(추천안) |
| T09 | 얼음 유지 시간 경과 | 사전 피드백 후 경로 소멸(추천안) |
| T10 | 빨강 용 돌진 중 일반 공중 적 접촉 | 공격 판정 동작; 돌진이 부자연스럽게 중단되지 않도록 피격 규칙 검증 |
| T11 | 게이지 100%에서 필살기 입력 | 3인 합동 공격 발동(연출·피해량 미확정) |
| T12 | 다단히트 중 연속 적중 | 기술 1회에서 PERFECT 기회 중복 생성 방지(잠정 규칙) |

### 10.3 레벨 디자인 검증 지표(권장)

- 태그 버튼의 최초 자발적 사용 시점.
- PERFECT 성공률의 변화 및 반복 후 학습 여부.
- 구간별 사망·실패·재시도 횟수.
- 직접 안내 없이 지형을 돌파한 비율.
- 보스전에서 이전 4개 스테이지에서 학습한 이동·태그 기술을 실제 사용했는가.

별도 원격 분석 시스템까지 구축하기보다, 짧은 플레이 관찰·메모·간단한 이벤트 로그만으로도 증거를 모을 수 있다.

## 11. 구현 전에 확정해야 할 주요 미결정 항목

**높은 우선순위**

1. **태그 선택 방법:** 고정 순서인가, 자유 선택인가? 자유 선택이라면 입력 방식은?
2. **기술 직접 사용:** 고유 기술 버튼을 제공하는가? 그렇다면 태그 자동 발동과 스킬 쿨타임 관계는?
3. **방향 결정:** 특히 파랑 빙결 활주는 4방향(좌/우/좌상/우상) vs 8방향? 아무 방향키도 입력하지 않을 때는?
4. **출현 위치/속도:** 새 캐릭터는 이전 캐릭터의 정확한 위치·속도를 계승하는가? 기술 시작 시 궤적이 끊기지 않는가?
5. **태그 스택 최종 채택:** 최대 2, 자연 회복 2초, PERFECT 1개 반환의 시험값을 유지할지?
6. **PERFECT 판정 공격 범위:** 기본 공격도 허용할지, 기술의 지정 타격으로 한정할지? 적 여러 명/다단히트 처리?
7. **빨강 돌진 방어 정책:** 공격 판정 외에 경직 면역, 접촉 공격 무시, 보스 공격 예외 등.
8. **파랑 경로 충돌 구현:** 대각선 경사 발판 충돌, 단방향 처리, 1.5초 경로 소멸 정책 확정.

**중간 우선순위**

9. 바람 상승 기술의 공격 판정 및 추가 효과.
10. 에코 공격이 이어지는 정확한 프레임/시간/대미지.
11. 게이지 충전량·조건, 필살기 대미지 및 사용 조건.
12. 캐릭터별 능력 수치, 물리·스프라이트 크기, 판정 시간 테스트.
13. 스테이지별 구체 맵, 체크포인트·리스폰·게임오버.
14. 적/보스 아트, AI 상태·경직 저항 정책.
15. Phaser 웹 개발 환경을 최종 선택할지 여부.

> **개발 에이전트 안내:** 미결정 항목을 숨겨서 확정 사양처럼 문서화하지 말 것. 진행 가능한 부분부터 최소 구현하고 가정을 남길 것.

## 12. 권장 개발 순서 및 범위 제어

### 12.1 단계별 우선순위

1. **핵심 재미 검증** — 빨강/파랑 2인 태그, 공격 적중 PERFECT, 에코 공격, 얼음 활주.
2. **3인 역할 검증** — 바람 상승 추가, 이동 경로 조합, 스택 흐름.
3. **Stage 1~2** — 태그 이동 학습과 PERFECT 전투 학습이 실제로 가능한가.
4. **Stage 3~4** — 전투/이동 연계 및 게이지·필살기.
5. **Stage 5** — 앞서 익힌 기술을 요구하는 보스.
6. **연출·최적화·테스트** — 도트 애니메이션, 타격감, 안내 UI, 버그 수정.

### 12.2 기능 추가 억제 기준

새로운 기능·기믹을 제안할 때 다음을 확인한다.

- 이 기능이 **태그 연계의 고유한 재미**를 강화하는가?
- 이 콘텐츠가 **핵심 시스템의 자연스러운 학습**을 돕는가?
- 5~10분 내 게임 경험에 꼭 필요한가?
- 기존 기술/오브젝트를 재사용하여 개발량을 줄일 수 있는가?

어느 목표에도 기여하지 않는 신규 기능은 보류한다.

## 13. 변경 이력 및 현재 확정 사항 요약

### 핵심 변경 이력

- 초기 10개 스테이지 계획 → **5개로 축소**, 마지막은 보스전.
- 태그 후 스킬 수동 발동 검토 → **태그 시 다음 기술 자동 발동(A안) 확정**.
- PERFECT 판정은 모션 타이밍이 아니라 **공격 적중 직후**로 확정.
- 이동에서 PERFECT 특별 보상 제외.
- 태그 단일 쿨타임 대신 **2회 충전형 스택을 유력한 프로토타입 안으로 제안**.
- 3인 공용 연계 게이지 및 3인 합동 필살기 채택.
- 캐릭터 기술 변경: 빨강 **용 변신 화염 돌진**, 파랑 **얼음 경로 생성 자동 활주(A안)**, 바람 **상승 기류**.
- 파랑은 얼음 지형을 자유 배치하는 B안이 아니라 **방향 지정 후 경로를 만들면서 자동 이동하는 A안** 채택.
- 포트폴리오 목표를 **핵심 재미 시스템 구현 + 튜토리얼형 레벨 디자인 역량 입증** 두 가지로 확정.

### 한 문장 게임 정의

> **세 캐릭터의 이동·전투 기술을 태그로 연결하고, 공격 적중 직후의 PERFECT 태그로 에코 공격과 연속 연계 보상을 얻으며, 다섯 개의 점진적 학습 스테이지를 거쳐 최종 보스를 공략하는 2D 도트 액션 플랫포머.**
